**Status values:** `Not fixed` · `In progress` · `Fixed (<commit>)` · `Needs confirmation` · `Won't fix (<reason>)`.

**Severity:** Critical = an exploitable security hole or data-loss bug reachable today · High = a correctness bug users will hit, or a security weakness needing a circumstance · Medium = a latent bug, race or robustness gap · Low = quality, performance or minor hardening.

**Wave tag:** every recommended fix carries its execution wave — **[Wave G]** security and correctness that bites now · **[Wave H]** latent bugs and races · **[Wave I]** hardening, architecture and test coverage.

## Priority waves

- **Wave G — fix now.** 13 items, run as three batches, each landing with a test that fails when the defect is planted:
  1. **Exposure & injection** — small, self-contained, and the worst to hear about from someone else: `SEC-28` a public page listing every registered user, `SEC-26` a sanitiser that executes what it strips, `SEC-22` an unsanitised imported thumbnail, `SEC-24` an unvalidated provider endpoint reachable into the private network.
  2. **Access control** — `SEC-23` cross-organisation bundle invitations, `SEC-27` permanent write access for a past reviewer, `SEC-25` case-variant duplicate accounts.
  3. **Silent data loss & engine correctness** — `DATA-33` a version never bumped so the next save reverts it, `ENG-20` the containment-cycle breaker skipped on the import path, `CANVAS-10` stale pan/zoom inside memoised renderers, `SIM-02` and `SIM-03` gateway routing and the runaway guard, `IO-11` a quadratic parse on malformed input.
